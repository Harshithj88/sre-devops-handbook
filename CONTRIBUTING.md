# Contributing

Thank you for your interest in contributing to this SRE / DevOps Handbook.

## How to Contribute

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/your-addition`)
3. Make your changes
4. Commit your changes (`git commit -m "Add: description of your change"`)
5. Push to your branch (`git push origin feature/your-addition`)
6. Open a pull request

## What to Contribute

Contributions are welcome in the following areas:

- **New runbooks** — troubleshooting guides for common production issues
- **Cheat sheets** — quick command references for DevOps tools
- **Checklists** — production readiness or operational checklists
- **Architecture diagrams** — Mermaid-based diagrams for common patterns
- **Documentation** — SRE/DevOps concepts and best practices
- **Scripts** — automation examples (PowerShell, Bash)
- **Corrections** — fixing errors, outdated information, or broken links

## Guidelines

- Use Markdown for all documentation
- Use Mermaid for diagrams (supported natively by GitHub)
- Follow the existing file structure and naming conventions
- Keep content practical and actionable
- Include real commands and examples where possible
- Do not include any proprietary or confidential information
- Use code blocks with language tags for all commands and scripts

## File Naming

- Use lowercase with hyphens: `my-new-runbook.md`
- Place files in the appropriate directory (`runbooks/`, `cheatsheets/`, etc.)
- Use the existing templates in `templates/` when creating new runbooks or postmortems
